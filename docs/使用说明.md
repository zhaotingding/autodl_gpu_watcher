# 使用说明

本页说明应用里的操作。环境安装、管理员权限和启动命令见 [README](../README.md)。只需要 SSH 训练监控时，可直接看第二节，无需配置 AutoDL 或 AI。

## 1. AutoDL 平台监控

### 准备自己的配置

公开 `config.yaml` 是安全示例，不包含维护者的 Telemetry 服务、账号或实例 ID。先按 README 创建 `config.local.yaml`，再编辑个人文件；应用优先读取 local 文件，两者不逐字段合并。

| 配置项 | 用途 |
| --- | --- |
| `telemetry.endpoint` | 本项目兼容的 GPU Telemetry 数据服务地址；需要自行提供，登录 AutoDL 不会自动生成此地址 |
| `occupancy.self_user` | 占用名单中的本人名称，也可在全局监控设置中保存个人偏好 |
| `monitor.poll_seconds` | 采样间隔；默认 60 秒，可在全局监控设置中调整 |
| `auto_start.targets` | 自动开机所需的个人实例映射；必须使用自己的入口、物理主机和完整实例 UUID |
| `auto_start.enabled` | 是否允许自动开机；只监控时保持关闭 |

未配置 Telemetry 时，首次界面会提示尚未配置；仍可添加独立 SSH 服务器。需要自动开机时，应先验证平台资源、实例身份和显存信息准确，再启用配置与界面中的电源选项。

### 登录、开始和停止

1. 进入“AutoDL 平台”，点击“登录 / 更新会话”。程序打开专用 Microsoft Edge 登录窗口。
2. 完成自己的登录，回到 AutoDL 私有云并确认能看到主机或实例页面。
3. 返回应用，点击“完成登录并关闭窗口”。程序请求专用浏览器正常关闭，等待资料保存并同步，再核验实际平台接口。
4. 等待状态变为登录有效。**资料同步完成不等于会话已经验证成功**；若仍失败，看状态和日志中的具体原因。
5. 选择入口，在右上角“全局设置 → AutoDL监控”填写本人名称、采样间隔并保存，再点击“开始监控”。
6. 点击“停止监控”请求安全结束；关闭应用也会等待当前任务收尾，不是强杀远端训练。

新配置默认仅监控。不希望开关服务器时，保持“启用真实自动开机”和“关闭本账号全部无卡实例”不勾选。已有偏好会恢复；不要把“新配置默认关闭”理解为程序会自动清除你以前保存的开启状态。

“关闭本账号全部无卡实例”会中断相应实例，须配合真实自动开机使用。电源功能只能操作明确配置并核验的本人实例；停止监控不会自动撤销已经完成的电源操作。

### 读懂状态

- “自动开机”列的“可开机”表示当前实例映射具备资格，不表示现在就会开机。还需电源选项、空位、显存及账号条件都满足。
- “训练SSH”列与平台登录独立：平台有实例，不代表 SSH 已配置；SSH 已连接也不能证明 AutoDL 登录有效。
- 平台资源、显存和占用名单随采样更新。共享物理 GPU 的不同入口可能显示相同 GPU 数据，不能仅凭图表相同判断串错实例。
- 明确登录失效会要求重新登录；Telemetry HTTP 断连、冷却或限流不等于 SSH 出错。冷却期间不会发起该轮 Telemetry 请求，也不会把旧数据用于开机。
- 可以在监控中修改并保存设置；**正在运行的任务保持原设置，下次开始监控时才采用新设置**。需要立刻切换电源选项时，保存后停止并重新开始。

## 2. SSH 训练监控

### 添加连接

先在普通 PowerShell 确认系统 OpenSSH 可用，再用自己的别名验证连接。将示例别名替换为你的真实配置：

```powershell
ssh -V
ssh my-training-server
```

应用使用已有公钥及已核验主机，不保存 SSH 密码；加密私钥需要可用的 SSH 代理。远端采集需要 Linux `/proc` 和 Python 3.7 以上标准库，GPU 信息还需要 `nvidia-smi`。本机的 Conda Python 与远端 Python 是两个不同位置，不要在“远端Python路径”填本机路径。

1. 进入“全局设置 → 服务器连接”，添加服务器或选择已有入口。
2. 填写 SSH 别名、远端 Python 路径，以及可选的项目目录和脚本筛选范围。
3. 保存连接，在对应页面点击“开始训练监控”。独立服务器可以单独监控，不需要 AutoDL 自动开机。
4. 各服务器按设置的间隔采集；切换标签不会停止采集。同一 SSH 别名不能在多个页面重复启动。

连接设置可在监控中编辑；正在采集的服务器继续使用旧连接，下次启动该服务器监控时生效。修改其他服务器不会切换当前监控入口。

### 有 tmux，但为什么没有训练卡片

`tmux ls` 只能证明会话存在，不能证明其中仍有训练进程。采集会结合进程、tmux、可读训练日志和可核验 GPU 进程发现任务；不只看脚本是否叫 `train.py`。

依次检查：

1. SSH 登录用户是否与运行训练的用户一致。
2. 配置的项目目录是否包含实际训练目录。
3. 是否设置了过窄的自定义脚本筛选；脚本名支持 `*`、`?`。
4. 进程是否仍存活，以及是否有权限读取其日志。

只有终端输出、没有可读日志，或只写二进制事件时，可能能看到进程但无法显示进度。不要把“进程存在”当成“训练正常”，也不要把“没有匹配卡片”直接当成“训练已退出”。原日志入口保留，无法解释的内容会显示原文摘要或未知状态。

### 读懂卡片与 GPU 表

| 显示 | 含义 |
| --- | --- |
| 绿色卡片 | 进程存在，并有可识别的训练或测试阶段证据 |
| 红色卡片 | 日志发现错误，或进程退出但没有确认正常完成；不会据此猜测退出原因 |
| 黄色卡片 | 连接失败、数据过期、日志不可读或长时间没有新进展等，需要查看具体文字 |
| `—`、未知、无法核验 | 没有足够证据，不能当作数值 0 |
| 开始时间、持续时间 | 由进程信息和最近确认存活的采样计算；断连或退出后不继续虚增 |

训练与各测试集各自保留轮次、Step 和指标，某一轮没有新测试结果时不会伪装成已有结果。单次测试结束不等于整个训练完成。

整卡显存、当前进程显存和训练日志上报的峰值分配量是不同指标。容器内 PID 可能不能对应宿主 GPU PID；此时会显示关联待确认，不把整卡显存冒充本人进程显存。容器 GPU 编号也不能直接当作平台 INDEX。

SSH 连接正常时复用已认证连接，失败后退避重试；界面分别显示采集次数和连接尝试次数。停止采集不停止训练，应用不会自动修改远端代码、杀进程或重启训练。

## 3. AI 专用监控规则（可选）

不用 AI 也能进行本地日志解析和监控。AI 需要外发日志片段，可能产生费用；它不能恢复日志中没有记录的信息。

1. 打开“全局设置 → AI规则与消费”。设置适用所有服务器，不是只针对当前页面。
2. 填写自己的接口地址、协议、模型、服务等级和密钥。服务等级可选 Flex 或 Standard，但实际接口和模型必须支持该选项。
3. 按需编辑全局监控提示词；它指导模型生成字段映射或文本提取规则。
4. 在训练卡片点击“生成 / 更新监控规则”，检查待发送片段，再生成并应用。
5. 查看主卡片的实际规则状态；验证失败或新日志不匹配时，继续默认监控并显示原因，可手动更新规则。

规则只负责解析日志字段，不执行模型给出的任意 Shell 或 Python。生成成功后，后续采样读取新日志并在本地应用规则，不逐轮重复收费调用。

“新训练自动生成监控规则”默认关闭；主动开启并保存后，新任务首次有可读日志时可自动请求。失败不会自动不断重试，关闭窗口也不能撤回已经发给服务商的请求。

密钥存入 Windows 凭据管理器，普通 AI 配置在 `.ui/ai.yaml`，专用规则在 `.ui/training_rules.yaml`，用量账本在 `.ui/ai_usage.sqlite3`。保存密钥成功不代表已经通过接口验证。

“用量与消费”查看输入/输出 Token、缓存明细及估计金额。请在计价设置中填写适用自己服务商和模型的价格；估计金额不等于最终账单，不应把文档里的历史模型价格当成现价。

## 4. 应用图标

进入“全局设置 → 应用图标”，导入 ICO 或 PNG。窗口图标可立即更新，偏好保存后下次恢复。

- ICO 保留原文件及全部尺寸帧；PNG 保留透明度和比例，按需要生成各尺寸。
- 源码直启可以更换窗口图标；只有从轻量 EXE 启动时，才会在正常关闭后同步对应的 EXE 图标。
- 窗口、磁盘 EXE、快捷方式和固定任务栏入口可能使用不同图标来源。更换后刷新目录或重新打开；旧固定入口可能需要重新固定。
- EXE 本身支持直接双击。需要桌面快捷方式时，从轻量 EXE 打开的应用里选择“另存启动快捷方式”，它会保留所选 Conda 环境和管理器参数。换环境名后重新导出旧快捷方式。

图标偏好及副本在 `.ui/`，不依赖最初导入文件一直保留在原处。

## 5. 出问题时看哪里

| 问题 | 优先查看 |
| --- | --- |
| 安装失败、`WinError 5`、找不到模块 | [README 的常见问题](../README.md#常见问题)，以及 PowerShell 完整输出 |
| GUI 启动失败 | 错误提示给出的日志路径；若已生成，通常为资料根 `.ui/startup.log` |
| 平台监控失败 | 界面底部状态和日志；默认日志位置为 `runtime/logs/watcher.log`，个人配置可改变位置 |
| SSH 断连或训练数据不完整 | 对应服务器页面的连接错误、筛选范围和训练原日志 |
| AI 规则无法应用 | 生成窗口、卡片回退原因、用量与消费页面 |

报告问题时区分本地环境、平台 HTTP、训练 SSH 和 AI 请求。不要把不同连接的失败都归因为“暴力扫描”，也不要通过高频反复点击开始来验证。提交诊断信息前移除密钥、个人服务地址及不愿公开的日志。
