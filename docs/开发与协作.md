# 开发与协作

首次使用请先阅读 [README](../README.md)。本页面向修改代码、测试与构建；基础业务配置见 README 的“首次使用”。

## 先确认 PowerShell 权限

创建环境以及安装、更新、卸载依赖都需要目标目录的写权限。**目录 ACL 限制普通用户写入时，更新安装需相应权限，通常使用管理员 PowerShell**；用户可写的环境用普通窗口即可。目录所有者名称不能单独证明权限，拒绝访问也可能源于占用或安全软件。已有有效环境按 B 路线保留，不为规避权限问题另建环境。打开管理员窗口后须重新进入仓库，用 `Test-Path .\pyproject.toml` 确认位置。正常源码/EXE 启动、测试和构建通常只需普通窗口及可写的项目/临时目录。

`(base)` 不是权限标志，也不影响显式的 `conda run -n auto-gpu` 选择。遇到环境内 `.pth` 文件的 `WinError 5`，不要改用 `--user`；详细排错见[README](../README.md#常见问题)。

## 一次安装，使用自己的服务器

本项目面向开发者，运行方式为“源码 + 项目专用 Conda 环境 + 可选轻量 EXE 启动器”。开发者自行准备 Conda；不自动安装 Conda，不向公共 base、全局 Python 或用户 site 安装依赖，不创建或依赖 `.venv`。安装、源码和测试命令通过 `conda run -n <项目环境名> --no-capture-output` 明确选择环境并实时输出；EXE 支持直接双击，内部使用 Conda 启动默认项目环境。

完整桌面支持 Windows 10/11 和 Python >=3.10，建议 Python 3.11。SSH 监控需要 OpenSSH 客户端，先确认 `ssh -V` 与 `ssh <自己的别名>` 正常。平台登录使用系统 Microsoft Edge；无需另下载 Playwright 浏览器。其他操作系统尚未完整验收，不承诺 Windows 凭据、图标或平台登录功能可用。

```powershell
git clone "<从本仓库页面复制的克隆地址>"
Set-Location "<克隆后的仓库目录>"
conda --version
conda env list
```

默认环境名为 `auto-gpu`。先检查已有环境；当前 B 路线直接复用，不执行创建。新协作者先按 [README 的首次安装](../README.md#首次安装) 确认环境目标目录再创建，不删除、不重建、不叠加已有有效项目环境。

**安装窗口：环境不可写时使用管理员 PowerShell。** 安装与启动分开执行；安装退出码非 0 时不要继续。先安装：

```powershell
conda run -n auto-gpu --no-capture-output python -s -m pip install --no-user -e .
```

确认安装退出码为 0 后，回到普通 PowerShell，进入仓库再启动：

```powershell
conda run -n auto-gpu --no-capture-output python -s -m autodl_watcher
```

不需要手动激活，也不使用裸 `pip`、全局 Python 或用户 site。`--no-user` 明确将安装限定在环境中；`-s` 禁用用户 site，缺失依赖应在专用环境补齐。`--no-capture-output` 避免 Conda 缓存实时日志。检查 Tcl/Tk、项目版本与依赖：

```powershell
conda run -n auto-gpu --no-capture-output python -s -m tkinter
conda run -n auto-gpu --no-capture-output python -s -m autodl_watcher --version
conda run -n auto-gpu --no-capture-output python -s -m pip check
```

源码为 editable 安装，修改 `src/` 后重开应用即可运行新代码；普通业务改动无需重建启动器。兼容调试和 CLI 入口继续复用同一业务链：

```powershell
conda run -n auto-gpu --no-capture-output python -s tools/gui_entry.py --debug
conda run -n auto-gpu --no-capture-output python -s tools/run_watcher.py --help
```

调试模式强制关闭电源选项，但不会关闭旧设置中的自动 AI 规则生成；开始训练监控前单独检查该开关。如果使用其他项目专用环境名，将这些命令的 `auto-gpu` 一致替换；EXE 还要显式传同名 `--env`，不要使用 base。

## 可选轻量 EXE

完成专用 Conda 环境安装后，直接双击仓库根目录的轻量启动器即可，无需预先打开终端或激活环境。也可从 PowerShell 启动：

```powershell
conda run -n auto-gpu --no-capture-output .\AutoDLWatcher.exe
conda run -n auto-gpu --no-capture-output .\AutoDLWatcher.exe --debug
```

启动器无 `--env` 时固定选择 `auto-gpu`，不会继承另一个已激活的项目环境；其他专用环境须显式传 `--env <项目环境名>`。管理器按 `--conda`、`CONDA_EXE`、`PATH` 中的 `conda.exe` 定位，找不到时明确报错；双击时也须满足该条件。同一台机器有多套 Conda 时，可明确指定管理器与同一环境名，例如：

```powershell
conda run -n auto-gpu --no-capture-output .\AutoDLWatcher.exe --env auto-gpu --conda "C:/path/to/conda/Scripts/conda.exe"
```

不支持 `--python` 或项目 `.venv`。环境不存在、依赖缺失、选择 base 或找不到 Conda 时提示修复，不扫描全局 Python、不回退 base、不调用旧冻结 worker，也不自动安装依赖。GUI 使用选定环境运行源码，后台 Python 任务使用同一个环境及解释器。

EXE 只包含标准库启动代码，不包含本项目业务包、第三方依赖或项目 Conda 环境。它必须与仓库源码配套，不能当作独立安装包转移到另一台电脑；协作者仍须克隆仓库并自行准备环境。旧完整冻结成品和 `_internal/` 在新入口验证通过前保留，归档时保持配套，不混用两代入口。

## 个人配置与启动路径

- `config.yaml` 是安全公开示例，默认关闭电源操作，未填写作者的用户名、实例 UUID 或私有 Telemetry 地址。复制为 `config.local.yaml` 填写自己的参数；这个 local 文件不会进入 Git。
- `.ui/` 保存个人服务器、界面偏好、规则、AI 用量及图标；`runtime/` 保存登录会话、运行状态和日志。它们不会进入 Git 或轻量启动器构建目录。
- API 密钥仍由 Windows 凭据管理器保存；服务器配置只引用 SSH 别名，不复制私钥。AI 默认关闭，使用自己的服务配置后才可主动发送日志。
- `AUTODL_APP_ROOT` 显式指定资料根，适合测试和独立安装。未指定时，源码和仓库轻量 EXE 都使用源码仓库根；wheel 兼容安装用系统用户资料目录。Windows wheel 默认 `%LOCALAPPDATA%/autodl-watcher`。
- `config.local.yaml` 优先于同目录 `config.yaml`；后者不存在时，启动器从包内 `defaults.yaml` 初始化。目录存在或保存成功不等于平台/SSH/AI 已验证。

SSH-only 使用可以不配置 AutoDL 平台。需要平台显存及电源调度时，配置自己的 Telemetry 地址、本人占用标识和实例映射，先以仅监控模式核验；启用电源操作必须是操作者的明确选择。

## 验证与可选构建

依赖唯一声明为 `pyproject.toml`，不新增另一份手工维护的 requirements 列表，不顺带升级版本。测试继续使用项目专用 Conda 环境：

```powershell
conda run -n auto-gpu --no-capture-output python -s -m pip check
conda run -n auto-gpu --no-capture-output python -s -m unittest discover -s tests -q
```

离线测试使用合成样本、模拟网络和临时目录，不需要作者的 `.ui/`、SSH、平台账号、API 密钥或已构建 EXE。独立环境验收应清除继承的 `PYTHONPATH`、`PYTHONHOME` 并禁用用户 site，核对第三方包实际来自所选环境；环境名、`pip install` 成功或打开一个窗口不能单独证明未借用外部包。不要在普通测试中连接真实服务器、调用收费 AI 或执行开关机。

只在需要可选 EXE 时安装构建 extra；固定 PyInstaller 版本仍在 `pyproject.toml`。**安装构建依赖需要环境写权限，按目录 ACL 决定是否使用管理员 PowerShell；随后构建可在普通窗口执行。**

```powershell
conda run -n auto-gpu --no-capture-output python -s -m pip install --no-user -e ".[build]"
```

安装成功后，在有仓库写权限的普通窗口构建：

```powershell
conda run -n auto-gpu --no-capture-output python -s tools/build_exe.py --stage-only
```

脚本只把单文件轻量启动器暂存到 `.tools/build/launcher/AutoDLWatcher.exe`，不覆盖根目录旧程序，不生成 `_internal/`、冻结业务 worker 或完整安装包。PyInstaller 单文件内部仍含其引导代码所需的最小运行时；它不作为业务运行环境，应用和业务依赖始终由选定的项目 Conda 解释器提供。普通源码变更无需重建，启动器实现或图标资源变更时才需要。

构建后按下一节备份旧入口并测试新入口；旧完整冻结程序的 EXE 与 `_internal/` 必须配套保留。不要移动或覆盖 `config.local.yaml`、`.ui/`、`runtime/` 等个人资料。构建成功不等于启动验证通过：还应检查默认项目环境、`--env` 指定环境、环境缺失、依赖缺失、拒绝全局/base 回退，以及 GUI 与 worker 的解释器、停止和退出行为。源码窗口、启动器窗口和后台采集应分别记录实际结果；离线测试不能代表真实平台或其他操作系统已验收。

### 将构建结果放到仓库根目录

**普通 PowerShell，仓库目录需可写。** 构建后先检查 `.tools/build/launcher/AutoDLWatcher.exe` 已生成；它放在暂存目录时不具备仓库根布局，不能只在那里双击就判断启动失败。正常关闭现有应用后，在仓库根目录执行下列命令，备份旧入口，再用新入口启动验证：

```powershell
if (-not (Test-Path .\.tools\build\launcher\AutoDLWatcher.exe)) {
    throw '没有找到构建结果，请先完成构建。'
}
if (Test-Path .\AutoDLWatcher.exe) {
    $launcherBackup = Join-Path .\.tools ('AutoDLWatcher-before-' + (Get-Date -Format 'yyyyMMdd-HHmmssfff') + '.exe')
    Copy-Item .\AutoDLWatcher.exe $launcherBackup -ErrorAction Stop
}
Copy-Item .\.tools\build\launcher\AutoDLWatcher.exe .\AutoDLWatcher.exe -Force -ErrorAction Stop
conda run -n auto-gpu --no-capture-output .\AutoDLWatcher.exe
```

出现文件占用错误时，先确认原应用及其本地辅助任务已退出，不要强行删除占用文件。新入口验证失败时，可正常关闭它并从 `.tools/AutoDLWatcher-before-时间.exe` 恢复旧入口。若旧版还依赖 `_internal/`，验证完成前应保留该目录；本段不会删除任何依赖或个人资料。图标资源与窗口图标需分别核对，构建默认图标不会自动继承个人设置；需要嵌入指定图标时给构建命令加 `--icon "自己的ICO或PNG路径"`。

### wheel 兼容性检查（可选）

wheel 仍支持标准 Python 安装，用于检查包资源和异目录安装，不是克隆仓库后的必需步骤。此检查在同一个项目 Conda 环境中暂时卸载 editable、安装本轮 wheel，再恢复源码安装，不另建或叠加环境；执行前停止该环境运行的应用。**该流程含卸载和安装，环境不可写时整段在管理员 PowerShell 执行；任一步失败都应停止检查并恢复 editable。**

```powershell
$projectSourceRoot = (Get-Location).Path
conda run -n auto-gpu --no-capture-output python -s -m pip wheel --no-deps . -w dist
$wheelPath = (Get-ChildItem dist/autodl_gpu_watcher-*.whl | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
conda run -n auto-gpu --no-capture-output python -s -m pip uninstall -y autodl-gpu-watcher
conda run -n auto-gpu --no-capture-output python -s -m pip install --no-user $wheelPath
$previousAppRoot = $env:AUTODL_APP_ROOT
$env:AUTODL_APP_ROOT = Join-Path $env:TEMP 'autodl-wheel-check'
Push-Location $env:TEMP
try {
    conda run -n auto-gpu --no-capture-output python -s -m autodl_watcher --version
    conda run -n auto-gpu --no-capture-output python -s -c "import sys; from pathlib import Path; import autodl_watcher; assert Path(autodl_watcher.__file__).resolve().is_relative_to(Path(sys.prefix).resolve()); print(autodl_watcher.__file__)"
    conda run -n auto-gpu --no-capture-output python -s -m pip check
}
finally {
    Pop-Location
    if ($null -eq $previousAppRoot) { Remove-Item Env:AUTODL_APP_ROOT }
    else { $env:AUTODL_APP_ROOT = $previousAppRoot }
    conda run -n auto-gpu --no-capture-output python -s -m pip install --no-user -e $projectSourceRoot
}
```

CI 使用 [setup-miniconda 官方动作](https://github.com/conda-incubator/setup-miniconda) 为每个 Python job 准备一个 `auto-gpu` 专用环境；安装和离线测试均用 `conda run`，wheel 检查在同一环境轮替安装，并从临时目录确认模块实际位于该环境。项目依赖不装到 base，不连接服务器，也不执行付费 AI 或电源操作。`activate-environment`、`python-version` 和 PowerShell 支持按该动作的官方文档核对；当前 CI 配置不能替代尚未运行的云端 job 结果。

## 提交贡献

先阅读根目录 [AGENTS.md](../AGENTS.md) 的项目约束与技能索引；按当前任务读取匹配技能及必要 references。新增业务先搜索现有实现；纯计算、采集 IO、调度和 Tk 展示保持单向职责，源代码和 CLI 复用同一业务链路。关键注释解释原因、单位、时间语义和资源所有权，避免逐行翻译代码。

每次修复附上可复现的离线样本或最小回归，说明行为变化、验证范围及未验证内容。使用中文 Git 提交，检查 `git diff --cached` 确认没有个人配置、日志、密钥、私钥或训练资料。不要因为某模块旧而删除有效功能，不在普通回归中启动真实训练、产生 API 费用或执行电源动作。

请使用分支提交，项目不要求贡献者使用作者本机路径、Conda 名称或历史归档。共享接口变更同步调用方、测试和文档；提交 PR 前以一份没有 `.ui/`、`runtime/` 或 `config.local.yaml` 的干净检出完成安装与测试。
