# 配置迁移与历史资料维护

适用本仓库v0.9.9对应实现；本轮资料整理核对日期2026-10-15。详细历史证据保留原验证日期与实际/模拟/待验证状态，当前代码与事实优先。个人任务Skill提供通用方法，本技能只补项目特殊约束；历史记录不授予外部操作权限。

此路径保留以兼容既有文档链接；其他用途从[项目索引](../../../AGENTS.md)选择匹配技能，无需先读取本技能。

## 主要流程

1. 设置兼容或资料定位问题读取[设置和资料根](references/windows-and-data.md#设置和资料根)；只有查找历史证据、归档或恢复时读取[证据定位](references/windows-and-data.md#历史证据定位)。
2. 区分应用YAML、兼容旧JSON、协议/运行状态JSON及SQLite语义；同名YAML优先，损坏YAML不回退旧内容。已有文件不覆盖，规则身份和凭据保存边界不变。
3. source_root与application_root各有职责，AUTODL_APP_ROOT只覆盖资料。保留config.local.yaml、.ui、runtime、.env、账本、全部图标和用户改动；不因旧或未跟踪而删除。
4. 迁移和恢复先用隔离样本验证，个人资料变化时核对实际旧输入和保留结果。仅清理明确失效的停止文件或本轮可再生产物，不把旧.ui/runtime整体覆盖当前资料。
5. 配置相关使用test_yaml_settings.py、test_portable_startup.py或偏好恢复离线用例。仅整理技能资料时检查元数据、索引、引用及知识覆盖，无需业务回归、重启应用或构建EXE。

按任务选读，不要求先加载其他项目技能。完整行为契约和既有验收仅在需要时查[重构开发规范](../../../重构开发规范.md)和[验收记录](../../../docs/重构验收记录.md)。
