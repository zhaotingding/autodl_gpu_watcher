# 专用规则、AI请求与用量

适用v0.9.9的规则生成、缓存适用性、全局AI设置与账本维护。资料整理核对日期2026-10-15；历史实际/模拟证据沿用原验证日期，本轮未调用AI。证据定位按需见[归档映射](../../autodl-maintenance/references/windows-and-data.md#历史证据定位)，无需先读配置维护技能。

## 规则生成前的任务边界

输入日志须属于当前服务器、任务启动身份与日志来源；PID不匹配在任何收费请求前拒绝。启动器和真正训练进程必须区分，否则会生成针对错误日志的规则。证据：2026-10-08实际rules-4090-development/live-before.json与live-after.json，按钮联动及PID拒绝为test_v0811.py模拟回归。身份发现算法修改时才另读训练监控技能。

## AI规则、计费与收尾

- 全局`.ui/ai.yaml`用于所有服务器；API密钥按基础地址保存在Windows凭据管理器。保留协议、模型、Flex、可配置提示词和调用时计价。旧ai.json/training_rules.json只作兼容读取，不再作为新保存路径。
- `.ui/training_rules.yaml`按连接范围、任务启动身份和日志来源验证缓存；按各服务器采样间隔本地解析后续日志，不逐轮调用AI。规则仅字段路径/受限模板，不运行Python或Shell，不判断电源、不清除错误。
- Q10历史外层日志时间比JSON time晚约0.76ms，严格时间比较曾拒绝有效规则；按原记录位置应用，未覆盖行由默认解析处理，规则窗口读取主卡片实际适用状态。
- 请求前先记录已尝试，自动模式每任务一次。更新失败、空结果、保存失败和中断均保留旧有效profile，不自动收费重试。首次空规则仅对已有解析器识别的结构化日志产生经原样例验证的本地规则，并明确标注来源；未知格式维持默认监控。
- 日志选择优先已经确认progress_line的来源，再看文件名/mtime。CACHE/caching有steps进度，而更新更频繁的cache_trace.jsonl可能只有索引哈希；不能用mtime覆盖训练证据，也不能靠文件名猜阶段。
- `.ui/ai_usage.sqlite3`单独记录返回Token、缓存用量和调用时单价，包括规则无效的请求。未知保持未知，修改价格不重算历史；旧账本不补造用量。
- AI退出先拒绝新请求、等待网络宽限并落盘已知用量/中断。2秒仅是网络宽限，磁盘收尾仍须完成；响应头前Requests没有公开可靠跨线程取消，不能声称关闭程序取消了服务商计费。
- 收尾期间的规则更新只安排本地补解析，不多发SSH；用量查询后台只持账本和队列，不持Tk窗口。

证据：2026-10-07 v0.8.8实际日志/用户规则本地回放及模拟API，`ai-usage-development/`；2026-10-10空规则/旧规则保留为模拟`v0901/ui-report.json`，日志选择为一次实际只读`v0901/live-before.json`加本地回放；2026-10-14/15生命周期、安装与纯解析离线验收见仓库`docs/重构验收记录.md`、`test_ai_lifecycle.py`、`test_training_ai.py`、`test_training_ai_usage.py`、`test_training_rules.py`。旧版标签栏按钮位置不作当前布局约束，当前以全局设置入口为准。
